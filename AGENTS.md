# AGENTS.md

This file applies to the entire repository.

## Project Mission

Perler Beads Studio is a desktop application for converting user images into editable Perler bead pattern sheets.

The product must treat AI as an assistant, not as the final source of truth. AI may optimize, simplify, remove backgrounds, or generate reference images. The final bead grid must be generated by deterministic local logic so that the result is editable, countable, printable, reproducible, and tied to real bead palettes.

## Current Stack

- Desktop shell: Electron
- Renderer: Vue 3 + TypeScript
- Styling: Tailwind CSS
- Icons: `@iconify/vue` with RemixIcon icon names
- Build tool: electron-vite
- Package manager: npm
- Primary shell on this machine: Windows PowerShell

## Repository Structure

```text
src/main/
  Electron main process. Owns native window setup and privileged IPC handlers.

src/preload/
  Safe bridge exposed to the renderer through contextBridge.

src/shared/
  Shared TypeScript contracts used by main, preload, and renderer.

src/renderer/
  Vue application entry and renderer HTML.

src/renderer/src/
  Vue components, composables, data, styles, and browser-side utilities.
```

Important files:

- `src/main/index.ts`: Electron window setup, native theme IPC, AI model-list IPC.
- `src/preload/index.ts`: exposes `window.perler`.
- `src/shared/ai.ts`: AI provider and model-list result types.
- `src/shared/theme.ts`: theme and bridge types.
- `src/renderer/src/App.vue`: current main workbench UI and interaction state.
- `src/renderer/src/composables/useTheme.ts`: theme persistence and system-theme handling.
- `src/renderer/src/data/studio.ts`: static workflow and provider presets.
- `src/renderer/src/data/palettes/`: manufacturer palette configuration files.
- `src/renderer/src/utils/pattern.ts`: image-to-pattern conversion, sample pattern generation, PNG export.

## Architectural Rules

### Main Process

- Keep privileged behavior in `src/main`.
- Put network calls that require API keys or bypass browser CORS in main-process IPC handlers.
- Validate all IPC inputs. Do not trust renderer payloads.
- Do not expose Node.js APIs directly to the renderer.
- Keep `nodeIntegration: false` and `contextIsolation: true`.

### Preload Bridge

- Expose narrow, task-specific APIs through `window.perler`.
- Keep bridge methods typed in `src/shared`.
- Do not expose raw `ipcRenderer`.
- Add bridge functions only when the renderer genuinely needs a native or privileged capability.

### Renderer

- Renderer code should treat `window.perler` as optional so static browser previews still work.
- Keep UI state local until there is a clear persistence model.
- Keep expensive pattern rendering and image processing isolated in utilities or composables.
- Do not put API keys into project files or export artifacts.

### Shared Types

- Put cross-process contracts in `src/shared`.
- Shared files must remain dependency-light and should not import Vue, Electron runtime objects, or browser-only APIs.

## AI Integration Rules

The intended AI provider shape is:

```text
provider name
baseUrl
apiKey
model list
model capability tags
```

AI provider integration must follow these constraints:

- Treat user-configured providers as OpenAI-compatible, not universally compatible.
- Normalize `baseUrl` before appending provider endpoints.
- Model list fetch should target `/models` unless the user later configures a custom model-list endpoint.
- Model list output is not reliable for capability detection. Let users manually tag model capability later.
- Keep API key handling out of regular localStorage. Use in-memory state now; later use OS credential storage.
- During local Web preview development, browser-side AI calls are allowed only for explicit user-triggered tests and must not persist API keys.
- Do not ship a platform-owned API key inside the desktop app.
- For commercial first-party credits, route calls through a backend proxy with auth, quota, logging, and abuse controls.

Current AI implementation:

- `src/main/index.ts` has `ai:list-models`.
- `src/main/index.ts` has `ai:optimize-image`, routed through the main process.
- `src/preload/index.ts` exposes `window.perler.ai.listModels`.
- `src/preload/index.ts` exposes `window.perler.ai.optimizeImage`.
- `src/renderer/src/App.vue` can request model lists and display validation errors.
- `src/renderer/src/App.vue` can send an imported image to the configured image-edit model, receive an AI reference image, and pass that reference through the deterministic pattern pipeline.
- Local Web previews on `localhost`/`127.0.0.1` may use browser-side AI calls for development testing when the Electron bridge is unavailable.

Not implemented yet:

- AI-generated image from text-only prompts.
- Model capability tagging persistence.
- Secure credential storage.

## Pattern Generation Rules

The deterministic pattern pipeline is the product core.

Current palette registry:

- `MARD 221` is the default palette.
- `MARD 291`, `Perler`, `Hama`, `Artkal`, and `Artkal Mini` are configured from Bitbead color chart data.
- Add future manufacturers as new files under `src/renderer/src/data/palettes/` and register them in `src/renderer/src/data/palettes/index.ts`.

Current pipeline:

```text
image file
-> FileReader data URL
-> HTMLImageElement
-> center-crop draw to canvas at board dimensions
-> pixel readback
-> transparent pixels become no-bead cells
-> nearest palette color
-> optional Floyd-Steinberg dithering
-> editable grid cells
```

Guidelines:

- Keep final grid generation deterministic.
- AI output, if used, must become an intermediate image reference and still pass through the deterministic grid generator.
- Transparent source pixels must remain no-bead cells and must not be matched to black.
- Semi-transparent pixels should be composited against white before palette matching to avoid dark fringes.
- Prefer perceptual color matching in future work. RGB distance is acceptable only as the current MVP baseline.
- Real manufacturer palettes should preserve manufacturer code, color name, RGB, and later Lab values.
- Board settings must always stay in sync with generated grid dimensions.
- Avoid irreversible transformations when users may want to edit or regenerate.

Future pattern work:

- Lab/CIEDE2000 matching.
- Region smoothing and isolated-pixel cleanup.
- Palette reduction by selected manufacturer inventory.
- Bead count export grouped by manufacturer code.

## Editor Rules

Current editor tools:

- Pencil
- Fill
- Eyedropper
- Eraser
- Undo
- Redo
- Project save/open
- PNG export

Editing rules:

- Every destructive grid edit must push undo history first.
- Keep redo history until the next new edit.
- Do not mutate `patternGrid.cells` in place without updating Vue state.
- Limit undo history size to avoid runaway memory usage.
- Grid dimensions must come from the active `PatternGrid`, not from selected UI values alone.

Future editor work:

- Drag painting.
- Selection and move/copy/paste.
- Region replace color.
- Mirror, rotate, crop.
- Zoom and pan.
- Keyboard shortcuts.
- Canvas/WebGL renderer for large boards.

## Export Rules

Current export:

- PNG printable chart with coordinate rulers, bead IDs, heavy 5-cell grid lines, and a bottom bead legend.
- CSV bead inventory grouped by manufacturer color code.

Future export targets:

- PDF print sheet.
- Tiled multi-page print layout.
- Row/column labels.
- Symbol chart for low-color printing.
- Printable bead count table.
- Project package export.

Print/export output must be reproducible from saved project data.
Do not add watermarks to exported pattern sheets unless the user explicitly asks for branded output.

## Project File Rules

The current project format is JSON with a `.pbd.json` extension. It stores board settings, AI provider metadata without API keys, and the current editable grid.

Recommended future packaged `.pbd` shape:

```text
project.json
source-image.png
ai-reference.png
preview.png
```

`project.json` should include:

- app schema version
- board dimensions
- board shape
- manufacturer palette snapshot
- grid cells
- source image metadata
- AI provider/model/prompt metadata without API key
- export settings
- edit timestamp/version metadata

Never store API keys in project files.

## UI And Design Rules

This is a desktop workbench, not a landing page.

- First screen should be the usable workbench.
- Keep controls dense but readable.
- Prefer tool icons for editing commands.
- Use buttons with icons for commands.
- Use selects for provider/model/mode choices.
- Use sliders or numeric inputs for numeric settings.
- Keep panels flat. Do not nest decorative cards inside cards.
- Avoid marketing copy in the app surface.
- Do not introduce decorative orbs, bokeh blobs, or one-note gradients.
- Make 1280px width a minimum quality target.
- Ensure text does not overflow compact controls.
- Test both light and dark themes after visual changes.

Color direction:

- Neutral ink background and panels.
- Accent colors from bead-like coral, mint, amber, violet, and sky.
- Avoid making the whole UI dominated by one hue.

## TypeScript And Code Style

- Use TypeScript for all application code.
- Prefer explicit interfaces for cross-module data.
- Keep comments rare and useful.
- Use `computed` for derived Vue state.
- Use `ref` for mutable UI state.
- Keep renderer utilities browser-safe unless explicitly named otherwise.
- Keep main-process utilities free from DOM assumptions.
- Avoid `any`. If an external payload is unknown, type it as a narrow expected shape and validate.
- Do not add new dependencies without a clear need.
- Do not add abstractions before there is repeated complexity to remove.

## Security Rules

- API keys must not be committed.
- API keys must not be exported in project files.
- Do not put a first-party provider key in renderer code.
- Do not expose raw Electron or Node APIs through preload.
- Keep external links opened through `shell.openExternal`.
- Validate remote URLs before use.
- Treat user images as private input. Do not upload unless the user explicitly invokes an AI action.
- AI image optimization must be triggered by an explicit user action and must show validation errors without silently uploading.
- Browser-side AI fallback is for local development previews only; production desktop behavior should prefer main-process IPC.

## Validation Checklist

Before finishing a coding task, run the relevant checks:

```powershell
npm run typecheck
npm run build
```

For UI changes:

- Open the local preview or Electron app.
- Check light and dark themes.
- Check 1280px width.
- Check for console errors.
- Confirm no obvious clipping or overlapping.

For pattern conversion changes:

- Test sample pattern.
- Test at least one imported image.
- Test board size changes.
- Test dither on/off.
- Test PNG export.

For AI provider changes:

- Test missing Base URL.
- Test missing API Key.
- Test invalid URL.
- Test provider returning empty model list.
- Test valid OpenAI-compatible `/models` payload.
